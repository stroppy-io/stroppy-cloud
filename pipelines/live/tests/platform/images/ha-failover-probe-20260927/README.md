# Контроллер HA для live-проверок

Тестовый Go-контроллер передаётся через `execution.additional_containers`.
На каждой БД он ждёт стартовый маркер Stroppy. Только узел, обслуживший
стартовую запись через ProxySQL, проводит отказ. Остальные контроллеры
остаются наблюдателями. Доступ к Docker ограничен сокетом собственной
одноразовой VM; перед stop/start проверяются точная метка контейнера БД,
единственность совпадения и совпадение `stroppy-run` с самим контроллером.
При ошибке после попытки stop контроллер пытается вернуть тот же контейнер.

Контроллер сравнивает все поля контрольных строк на каждой реплике,
останавливает primary, записывает новый маркер через прокси, сверяет две
оставшиеся реплики, возвращает primary и ждёт равенства строк на трёх узлах.
Это функциональная проверка доступности записи и восстановления; не проверка
сохранности всех подтверждённых транзакций под непрерывной нагрузкой.
Контроллер не рассчитывает TPS. Результат проверяется отдельным Stroppy SQL
сегментом; разрешённые ошибки во время отказа не заменяют эту проверку.

[Сборка и digest](image.json), [локальные проверки](validation.json).
Исходник снимка сохранён рядом. Сборщик `live/tools/build_ha_probe.py`
использует зафиксированный MySQL-драйвер из локального Go-модуля Stroppy;
образ публикуется отдельным dev-тегом с существующей локальной авторизацией.
Сервер и Graphene для этого контроллера не модифицируются.
