# Авторизация managed YDB по ключу сервисного аккаунта

Профиль Graphene хранит JSON-ключ сервисного аккаунта. Activity получает его
только на runner и передаёт Stroppy отдельным файлом 0600 через
`serviceAccountKeyFile`. Официальная библиотека `ydb-go-yc` внутри Stroppy
выпускает и кеширует IAM-токены, обновляет их по сроку из ответа IAM.
Собственного refresh loop и изменяемого `authTokenFile` больше нет.
Пользователь не управляет краткоживущими токенами.

Возможность образа определяется по `ydb_service_account_key_file=1` в
`stroppy version --json`. IAM TLS проверяется независимо от настроек TLS БД.
При явно заданном ключе ошибка не переключает подключение на учётную запись
VM. Новая авторизация требует образа с этой возможностью; старые образы
сохраняют разовый IAM-токен только для activity с deadline минимум за минуту
до expiry. Более длинный запуск старого образа отклоняется.

Ключ не включается в публичный конфиг, историю workflow и артефакты.
Публичный конфиг не содержит runtime-путь. Отдельные runtime-конфиг и key-файл
удаляются после выполнения, ошибки
или отмены. Контейнер Stroppy получает сам долгоживущий ключ, а не только
временный токен; это выбранная модель доверия runner/container.

Локально проверены получение/кеширование/повторная выдача через официальный
SDK с подписанным JWT и локальным TLS IAM, отказ issuer и восстановление,
отсутствие metadata fallback, права/удаление файлов и неизменность публичного
конфига. [Живая проверка новой сборки](ydb-sdk-key-20260928/README.md)
прошла: 15 минут, 83330 запросов, 0 ошибок, артефакты без ключа,
native telemetry и полное удаление ресурсов.

Исторические [попытки с token-файлом](ydb-iam-refresh-mirror-20260927/README.md)
сохраняются как доказательства предыдущей реализации, а не текущего SDK-режима.
Реальное ожидание истечения 12-часового токена в облаке не выполнялось.
