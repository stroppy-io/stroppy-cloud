# Обновление IAM-токена managed YDB

В исходниках реализовано обновление токена внутри сегмента. Реальная замена
токена и продолжение запросов подтверждены в [отдельной попытке](ydb-iam-refresh-retry-20260927/rotation-partial.json);
та попытка целиком не прошла из-за ошибки учёта SQL stream. Первая попытка остановилась до ротации
из-за контекста heartbeat проверки версии; [причина и доказательства](ydb-iam-refresh-20260927/README.md).
Для полного повтора исправлена привязка heartbeat к исходной activity. Сервер хранит ссылку на профиль Graphene,
activity разрешает реквизиты только на runner и проверяет `stroppy version
--json`. Образ с `ydb_token_file=1` получает путь к временному token-файлу.
Stroppy перечитывает его не позднее чем через секунду при следующем запросе
аутентификации SDK, не меняя исходную идентичность на metadata credentials.

Activity получает новый IAM-токен через 10 минут либо половину его оставшегося
срока, если она меньше. Замена файла атомарна, права 0600. Временная ошибка
refresh сохраняет ещё действующий токен и запускает повтор. Если срок истёк,
нагрузка останавливается с failed, а не с пользовательским cancelled.
Реквизиты и токены не включаются в долговечный конфиг и не журналируются;
временные файлы удаляются после завершения, отмены или ошибки.

Старые образы продолжают работать со статическим токеном только при deadline
activity, который заканчивается как минимум за минуту до истечения токена.
Отсутствие такого ограничения отклоняется до запуска нагрузки с объяснением,
что нужен образ с поддержкой обновления. Новые поля не передаются старому
образу молча. Runtime-файлы остаются отдельными от сохраняемых артефактов.

Проверены локально: атомарная ротация, временная ошибка выдачи, остановка по
истечению, очистка файлов, сохранность публичного конфига, отказ от metadata
fallback при заданном token-файле и ограничения старых образов. Реальная замена через YC подтверждена отдельно от успешности полного прогона.
[Повтор с исправленным Stroppy](ydb-iam-refresh-mirror-20260927/README.md)
на 10-й минуте получил от YC тот же действующий токен и тот же срок. Это
успешный renewal response, но не вторая фактическая замена и не продление
срока. Проверка отчёта различает эти случаи; отсутствие повторного сообщения
Stroppy при неизменном токене ожидаемо. Ожидание реального истечения
12-часового токена в облаке не выполнялось.

Дополнительная SQL-регрессия: успешный stream иногда менял Err() на
context.Canceled после освобождения query timeout. Ошибка воспроизведена
локально и исправлена сохранением terminal outcome курсора. Новый
[образ с исправлением](../../images/ydb-iam-rows-20260927/README.md)
используется в повторах без ослабления error threshold. Попытка с потолком
100 RU/s выявила реальные ResourceExhausted; для проверки обновления
реквизитов лимит serverless поднят до 1000 RU/s, reserved capacity=0.
