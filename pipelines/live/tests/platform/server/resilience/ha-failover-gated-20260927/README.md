# Patroni: failover после начала нагрузки

Run `4790c0e6-69b1-4ad1-8e3f-a5a06594827d`, PostgreSQL 17, три DB,
три etcd, HAProxy, runner. Запуск через Stroppy Cloud.

Контроллер ждёт первую успешную SQL-операцию основного четырёхминутного
сегмента, затем останавливает контейнер выбранного primary. Это устраняет
гонку предыдущего теста, где новый Stroppy подключался уже во время отказа.
Контроллер подтвердил запись через новый primary, точное равенство строк
на двух оставшихся узлах и на всех трёх после возврата прежнего primary.
Run completed: основной сегмент выполнил 563921 запрос, 45 ошибок
во время переключения сохранены в результате. Начальная и финальная SQL-
проверки прошли без ошибок. Cleanup, артефакты, native metrics и логи прошли
проверку. CPU всех восьми машин корректен до двух минут после завершения;
все acceptance checks этого сценария прошли.

Это управляемый stop/start процесса; не авария VM или диска. Время после
ответа Docker stop не является полным RTO. Ошибки SQL во время переключения
допустимы и сохраняются; стартовая и финальная проверки требуют нуля ошибок.
Доказательства находятся в [postgres/](postgres/).
