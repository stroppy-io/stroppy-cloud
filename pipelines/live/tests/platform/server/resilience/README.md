## Исправления сервера

- Неоднозначный ответ StartRun оставляет сохранённую команду pending. Проектор
  повторяет неизменный запрос с прежним ID. HTTP 201 подтверждает создание run
  на сервере, а не завершение запуска на стороне Graphene.
- Suite восстанавливается из сохранённых RunSpec ячеек в исходном порядке.
  Библиотека повторно не читается, дочерние run отдельно не запускаются.
- Отмена сохраняется до RPC и повторяется наблюдателем. Позднее событие running
  больше не стирает cancelling в PostgreSQL, включая suite.
- При ошибке чтения/записи результата run остаётся в очереди финализации.
  Сохраняются исходные время/причина terminal event и сырой результат; terminal
  status записывается последним.
- Временная ошибка статуса ребёнка suite не считается отсутствием workflow.
  Завершение suite повторяется после восстановления связи.
- Keep deadline читается из Graphene holdings, а не сдвигается на время
  восстановления сервера. Артефакты не считаются сохранённой инфраструктурой.
- При общем lint исправлено освобождение контекста WebSocket-подписки после
  завершения polling; ранний отказ подписки также явно отменяет контекст.

Предел автоматической повторной отправки — **24 часа от создания**. После него
сервер может наблюдать найденный run, но не создаёт отсутствующий заново:
Graphene гарантирует дедупликацию лишь в пределах Temporal retention. Старый
неоднозначный pending требует разбирательства; он не объявляется успешным или
failed автоматически. Для этой политики retention инсталляции должен быть не
меньше 24 часов; живая проверка retention остаётся в приёмке.

## Проверки и ограничения

20 новых тестов/подтестов восстановления проверяются с race detector; 14 локальных

[Отчёт](../acceptance/resilience-integration.json).
Новые fault-тесты также выполнены с race detector: 7 тестов/подтестов passed,

[Старые ограничения среды](environment-blockers.json) больше не воспроизводятся:

Оставшиеся границы проверки:

1. Успешная синхронизация пайплайнов и новая полная серверная приёмка.
   Пересборка Compose завершена; полный серверный integration suite прошёл

   heartbeat проверены targeted race-тестами; [команды](ydb-iam-refresh-retry-20260927/local-validation.json).

python3 pipelines/live/tools/server_resilience_checks.py
python3 pipelines/live/tools/live.py validate
# Выборочная интеграционная приёмка с Docker:

интеграционных тестов в его отчёте явно отделена от выполнения.

## Инструмент обрыва локальной связи

`live/tools/graphene_fault_proxy.go` собирается отдельным `go build` по имени
файла; build tag исключает его из обычных сборок модулей. Рабочий режим для
Compose — HTTPS CONNECT через `HTTPS_PROXY` на Docker bridge. Graphene endpoint
остаётся исходным: он же определяет имена образов. TLS между сервером и Graphene
сохраняется; содержимое запросов, токены и ответы прокси не журналирует.
Управление привязано к loopback: `POST /fault` с
`{"method":"*","seconds":30}` прерывает текущие соединения и временно запрещает
новые. Fault автоматически истекает; `seconds:0` снимает его сразу.
По завершении Compose возвращается к исходному окружению, затем прокси
останавливается. Режим reverse proxy с подменой Graphene endpoint не подходит
для публикации образов. В CONNECT нельзя выборочно перехватывать зашифрованный
StartRun; потеря его ответа проверяется отдельными интеграционными fault-тестами.
Живые fault-сценарии после восстановления публикации выполнены;
результаты — в [live-suite](live-suite-20260927/README.md).
