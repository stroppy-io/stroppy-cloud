# Проверка primary failover через сервер

Прогоны запущены через Stroppy Cloud:

| БД | Run ID | Состояние доказательств |
| --- | --- | --- |
| MySQL 8.4 Group Replication + ProxySQL | d1c531ed-2199-4049-98b2-44ccfa07a05e | PASS: смена writer, точные строки, возврат узла, native metrics, артефакты, cleanup |
| MariaDB 11.8 Galera + ProxySQL | 9ecc21d6-5a9c-451f-aab5-b1196ed07944 | PASS: те же проверки на трёх узлах |
| PostgreSQL 17 Patroni + etcd + HAProxy | 48021b46-d718-4dde-b0fb-a2aca859ec8f | FAILED: новый Stroppy начал подключение во время переключения; исправлена синхронизация теста, запущен полный повтор |

Входы, launch identity и наблюдения находятся в подпапке соответствующей БД.
Контроллеры переданы через `execution.additional_containers`, дополнительных
API сервера не потребовалось. Доступ к Docker — только из контейнера на своей
одноразовой VM, с проверкой меток принадлежности текущему run.

Отказ — stop/start контейнера выбранного primary. Сравниваются все значения
контрольных строк на каждой реплике до отказа, на двух оставшихся узлах во
время него и на всех трёх после возврата. Запись во время отказа идёт через
прокси и должна выполниться на другом узле. Это не авария всей VM/диска и не
доказательство сохранности произвольной непрерывной нагрузки. Показатель
`elapsed_seconds` контроллера считается после ответа Docker stop и не является
полным RTO, поскольку stop может ждать корректного завершения процесса.

Stroppy выполняет стартовую запись, четырёхминутный сегмент SELECT и финальную
SQL-проверку успешности контроллера. Во время отказа допускаются SQL-ошибки;
стартовый и финальный сегменты требуют нуля ошибок. Native показатели не
пересчитываются. Успех workload должен дополнительно подтверждаться логами
контроллера, телеметрией, доступностью артефактов и очисткой инфраструктуры.

MariaDB: 521571 запрос, 0 ошибок, native 2173.211 queries/s. Это показатели
SELECT, не TPS. [Patroni с ожиданием начала нагрузки](../ha-failover-gated-20260927/README.md)
