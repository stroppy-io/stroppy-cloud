# Проверка HA через сервер

Входы создаёт `live/tools/server_ha_live.py`; сохранённые launch intent содержат
Idempotency-Key. Все операции с облаком выполняет сервер через Graphene.

Два независимых теста: MySQL 8.4 Group Replication (single primary, две реплики)
и MariaDB 11.8 Galera (три участника). Каждый имеет отдельный ProxySQL и runner,
все машины размера S, keep выключен. Всего пять машин на тест. Артефакты
результата сохраняются по обычной политике pipeline.

Инициализация создаёт таблицу `stroppy.live_cluster_probe` и процедуру
`live_assert_cluster`. Stroppy вызывает её через ProxySQL в течение двух минут.
Каждый вызов проверяет состав кластера и обновляет одну строку; таблица не растёт
пропорционально числу итераций. При нарушении проверки SQL SIGNAL вызывает ошибку,
а порог `error_rate=0` делает сегмент неуспешным.

- MySQL: ровно три ONLINE-участника и один PRIMARY.
- MariaDB: размер 3, local state 4, ready ON, статус Primary.

Это проверка доступности кластера и записи через прокси. Она не доказывает
автоматический failover, прочтение строки с каждой реплики или отсутствие
задержки применения на всех участниках. Для этих утверждений нужны отдельные
проверки и доказательства. Native throughput берётся только из Stroppy.

В `mysql/` и `mariadb/` сохранены preview, валидированные тесты, launch intent и
ответ сервера. Статус выполнения и итоговые проверки находятся в общей
`tests/progress.csv`; успешная валидация входа не означает успешный workload.

Квоты перед запуском: два свободных VPC из шести, достаточно CPU/RAM/VM/дисков.
Вместе с аналитическим стендом — три активных теста, 12 машин. Node-exporter
переведён с Quay на официальный Docker Hub по тому же manifest digest;
доступность публичного registry из YC проверяется самим deploy.
