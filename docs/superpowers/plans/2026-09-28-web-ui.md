# Web UI Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Full-coverage SPA prototype for Stroppy Cloud: every resource from `STROPPY.MD` §16.12 has a screen, runs on a mock API client that swaps to the real one by one flag.

**Architecture:** `@grafana/ui` design system + TanStack Router/Query/Form/Table/Virtual. `openapi-fetch` typed client whose `fetch` is either `window.fetch` or `mockFetch` (in-memory store + simulated run progress). WS client has the same two implementations. Screens never know which one is active.

**Tech Stack:** see `web/AGENTS.md` §2 (verified by the spike in `web/src/routes/index.tsx` history: theme, fonts, icons, router search, form, uPlot all green).

**Spec:** `web/AGENTS.md`

## Global Constraints

- `@grafana/ui` 13.2.2 / `@grafana/data` 13.2.2 pinned equal. React 19. Vite 7 + `@vitejs/plugin-react` 5 (v6 needs Vite 8).
- Styles only via `useStyles2` + theme tokens. No literal colors/px (`web/AGENTS.md` §4).
- Every user-visible string via i18next, `ru` + `en` in one change (§10). Locale files are **per feature** (`locales/{ru,en}/<feature>.json`) so parallel workers never touch the same file.
- Icons: `public/gf/build/img/icons` (postinstall `scripts/copy-grafana-assets.mjs`); fonts: `public/gf/fonts` (committed). `window.__grafana_public_path__ = '/gf/'` in `index.html`.
- Route files: `src/routes/**`, tree generated by the vite plugin / `npx tsr generate`. Never edit `routeTree.gen.ts`.
- `grafana Link/LinkButton/PageToolbar/InteractiveTable` banned (§5).
- Mock mode: `VITE_API_MODE=mock` (default in `.env.development`), `real` otherwise. The switch lives in exactly two files: `api/client.ts` and `api/ws.ts`.
- Acceptance per area = walk the screens in the browser against mock, both themes, no console errors, `yarn build` + `yarn lint` green.

## Review Focus

1. Tenant switch while on a tenant page: every query key starts with `['t', slug]`; switching must not show the previous tenant's rows. Test: `queries/keys.test.ts` asserts prefix for every factory.
2. `bigint`-range integers (seeds, `18446744073709551615`) survive edit round-trip via `stringifyRequest`/`parseSchemaJSON` (existing `tests/contract.test.mjs`). The client middleware must use `stringifyRequest` for every body.
3. Terminal run states: WS topic unsubscribes when `status ∈ {completed, failed, cancelled}`; polling fallback stops. Test in `hooks/useTopic.test.tsx` with the mock WS.
4. `problem+json` with `validation.errors[]` maps to form fields by `path` (dotted/slashed paths, nested arrays). Test in `api/errors.test.ts`.
5. Empty/degraded overview (`source: synthetic`, `degraded_reasons`) renders an explicit banner, not a blank panel. Test snapshot of `RunOverviewPanel` with fixture.

## Foundation (Task F, done by the lead before fan-out)

**Files:**
- `src/api/client.ts` — `export const api = createClient<paths>({ baseUrl: '', fetch: apiFetch, bodySerializer: stringifyRequest })` + middleware: `Authorization: Bearer ${getToken()}`, `Idempotency-Key` on `:launch|POST /runs|POST /suite-runs`, 401 → `onAuthLost()`.
- `src/api/errors.ts` — `class ApiError extends Error { status; code; title; detail; validation?; problem }`, `toApiError(res)`, `fieldErrorsFrom(validation) → Record<path, string>`.
- `src/api/mode.ts` — `export const apiMode: 'mock' | 'real' = import.meta.env.VITE_API_MODE === 'real' ? 'real' : 'mock'`.
- `src/api/mock/store.ts` — in-memory `MockStore` (tenants, me, databases, workloads, tests, runs, suites, suiteRuns, schedules, shares, providers, webhooks, tokens, invites, audit, settings, admin). Seeded by `mock/seed.ts` with realistic fixtures (2 tenants, 24 runs across statuses, 6 databases across kinds, 5 workloads, 8 tests, 3 suites, 2 suite runs, 3 schedules, 2 shares, 3 providers, 2 webhooks).
- `src/api/mock/router.ts` — `route(method, pattern, handler)`; pattern `'/api/v1/t/:slug/runs/:id'`; handler `(ctx: { params, query, body, store }) => { status, json } | Problem`. `mockFetch(input, init)` matches and returns `Response`; unknown → 404 Problem. Latency 80–250 ms, `?__fail=1` support for error-state demos.
- `src/api/mock/handlers/*.ts` — one file per area (`public-me.ts`, `tenants.ts`, `settings.ts`, `catalog.ts`, `library.ts`, `runs.ts`, `results.ts`, `suites.ts`, `admin.ts`). Foundation ships `public-me.ts`, `tenants.ts`, `catalog.ts` (schemas from `src/schemas/*.json`), `runs.ts` list+detail+overview; area workers add the rest.
- `src/api/mock/simulation.ts` — ticks every 1 s: advances `running` runs through phases (`provisioning→deploying→workload→collecting→teardown→done`), appends events/log lines/metric samples, completes or fails; drives suite-run progress. Exposes `subscribe(topic, cb)` for the mock WS.
- `src/api/ws.ts` — `interface WsClient { subscribe<T>(topic, opts: { cursor?, onEvent(payload: T, cursor?) , onError }): () => void; status$ }`; `createRealWs()` (frames per `web/AGENTS.md` §8, reconnect w/ backoff, resume by cursor) and `createMockWs(simulation)`; `export const ws = apiMode === 'mock' ? createMockWs(simulation) : createRealWs('/api/v1/ws')`.
- `src/api/queries/keys.ts` — `keys.t(slug)`, `keys.me()`, `keys.admin()`, `keys.catalog()`; area files `queries/runs.ts` etc. export `queryOptions` + mutation helpers.
- `src/hooks/useTopic.ts` — `useTopic({ topic, queryKey, enabled, reduce? })` → `setQueryData` (batched via pacer `useBatchedCallback`).
- `src/lib/auth.ts` — `getToken()` (`VITE_DEV_TOKEN` ?? localStorage ?? 'admin'), `setToken()`, `onAuthLost` handler.
- `src/lib/config.ts` — `loadPublicConfig()` from `/api/v1/public/config`.
- `src/lib/i18n.ts` — i18next init with all feature namespaces merged; `useT(ns)` helper.
- `src/app/AppShell.tsx` — GitHub-like top bar (logo, tenant switcher, global search `/`, theme toggle, user menu), left nav (Dashboard, Runs, Library ▾, Suites, Schedules, Results ▾, Settings; Admin if platform admin), content `Outlet`. `src/app/PageHeader.tsx` (title, breadcrumbs, status badge, actions, tabs), `src/app/Page.tsx` (padding/max width), `src/app/AppLink.tsx`, `src/app/Toaster.tsx` (sonner themed), `src/app/ErrorState.tsx`, `src/app/EmptyState.tsx` wrappers, `src/app/hotkeys.ts`.
- `src/components/DataTable/DataTable.tsx` — `DataTable<T>({ columns: ColumnDef<T>[], data, sort, onSortChange, rowLink?, virtual?, emptyState, loading })` on react-table 9 + react-virtual, grafana tokens; `DataTableToolbar` (search, filter pills, facets).
- `src/components/StatusBadge.tsx`, `RelativeTime.tsx`, `KeyValueList.tsx`, `CopyText.tsx`, `ConfirmAction.tsx`, `TagsEditor.tsx`.
- `src/components/schema/SchemaForm.tsx` — generic schemapb renderer (protoJSON schema → TanStack Form fields → grafana controls): string/int/float/bool/enum/list/map/object; `Computed` shown read-only; `FieldActive` via TS engine (`schema/engine.ts`), custom widget registry by schema id/path.
- `src/helpers/*` — `format.ts` (bytes, duration, number, percent), `run-status.ts` (status → color/icon/label key), `dataframe.ts` (`RunMetrics → DataFrame[]` with `applyFieldOverrides` so axes show units), `time.ts`.
- Routes skeleton: `routes/__root.tsx` (providers, `notFoundComponent`, `errorComponent`), `routes/index.tsx` (redirect to default tenant), `routes/t/$slug/route.tsx` (layout: AppShell, `loader` ensures `/me` + tenant), `routes/s/$token.tsx` (public, no shell), `routes/me/route.tsx`, `routes/admin/route.tsx`, `routes/examples.tsx`.
