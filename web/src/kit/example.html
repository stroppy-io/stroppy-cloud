Everything in the kit

Plain HTML on the kit's CSS, and one script for charts. No framework, no build step, nothing loaded from the network. Each example has its markup under HTML.

Setup

Link the four stylesheets in this order, put class="st-doc" and a data-theme on <body>, and load chart.js if the page has charts. The theme can change at runtime: set the attribute, charts redraw by themselves. 

<link rel="stylesheet" href="tokens.css">
<link rel="stylesheet" href="fonts.css">
<link rel="stylesheet" href="base.css">
<link rel="stylesheet" href="chart.css">
…
<body class="st-doc" data-theme="system">   <!-- dark | light | system -->
…
<script src="chart.js"></script>

The styles apply only inside .st-doc; the variables (--st-*) are on :root and on every [data-theme], so a part of a page can have its own theme.

Palette

The variables of the current theme. Use them in your own CSS: color: var(--st-muted). tokens.json has the same values for code that is not CSS.

Themes

data-theme picks the palette with CSS alone: dark (also what a page without the attribute gets), light, or system — the reader's prefers-color-scheme. It works on any element, the nearest one wins, and an explicit dark or light beats the system preference. Print is always light, whatever the screen shows. No script is involved: the three panels below look right with JavaScript off.

Charts

StroppyChart.mount(target, series, options) draws a chart into an element (or a CSS selector), keeps it fitted to the element's width and redraws it when the nearest data-theme changes. It returns { destroy() }.

ArgumentShape
series[{ title, unit?, points: [[time, value], …] }] — the shape of a run's metric series. time in seconds or milliseconds since the epoch; value may be null (a gap). Colours go by position: series 1, 2, …
options.unitUnit on the axis and in the tooltip when the series don't say one.
options.heightHeight of the plot in pixels; 200 by default. The legend adds to it.
options.curve'smooth' (default, the app's look) or 'linear': straight segments between observations, nothing interpolated.
options.time'clock' (default, wall-clock labels) or 'elapsed': time since options.origin (default: the first point), as m:ss.
options.markers[{ at, label, tone? }]: phases and events as dashed vertical lines; at in the points' time units, tone one of the kit's tones.
options.kind, options.categories'bars' draws grouped bars, one group per category (histogram buckets, segments); points are [categoryIndex, value].
options.labelAccessible name of the drawn chart.

Two series, data from the page

Keep the data in a JSON <script> so the page stays readable; one legend entry per series appears when there is more than one.

Throughput over timetps
const series = JSON.parse(document.getElementById('tps-data').textContent)
StroppyChart.mount('#chart-tps', series, { unit: 'tps' })

One series, milliseconds, a gap, taller

A single series has no legend. A null value is a missing observation: the line breaks there and is never drawn across it.

p99 latencyms
StroppyChart.mount(document.getElementById('chart-p99'), [
  { title: 'p99', unit: 'ms', points: p99Points }   // [[ms, value | null], …]
], { height: 260 })

Many series

Up to eight distinct colours and dashes; the ninth starts over. With several series each has its own dash too, so they can be told apart without colour.

CPU by machine%
StroppyChart.mount('#chart-cpu', machines.map((m) => ({ title: m.name, unit: '%', points: m.cpu })))

Remove a chart

const chart = StroppyChart.mount('#chart', series)
chart.destroy()   // stops following the size and theme, empties the element

Charts over a static chart

A report can draw its charts without JavaScript — an SVG and a table of the numbers — and let the kit add the interactive one on top. StroppyChart.enhance(figure, series, options) mounts the live chart next to .st-chart-static and hides the static plot only after it is up: the figure gets data-st-chart="live" and an st-chart:live event fires. If anything fails — the script is blocked, missing or throws — the live container is removed, the figure gets data-st-chart="failed", st-chart:failed fires with the error, and the static chart stays. Print always uses the static plot. The numbers table is the page's; the kit never hides it.

Turn JavaScript off and reload: these figures show their static charts and tables.

Elapsed time, phases, a gap, two series

StroppyChart.enhance('#fig-tps', series, {
  unit: 'tps', curve: 'linear', time: 'elapsed', origin: 1760400000,
  markers: [{ at: 1760400000, label: 'load' }, { at: 1760400120, label: 'run', tone: 'primary' }],
})

Grouped bars: a latency histogram

StroppyChart.enhance('#fig-hist', data.series, { kind: 'bars', categories: data.categories })

A failed enhancement keeps the static chart

This figure asks for a chart with no series, so enhance fails on purpose. The static chart stays; the page can react to the event.

figure.addEventListener('st-chart:failed', (e) => console.warn(e.detail.error))
StroppyChart.enhance(figure, [])   // returns null

The contract

PieceWhose
Values, units, series names and order, the static SVG and the tableThe page. The kit infers, resamples and merges nothing.
.st-chart-figure, .st-chart-static, .st-chart-svg classes, data-series, data-toneThe kit styles them; series 1–8 have the same colour and dash (lines) or hatch (bars) in the SVG and the live chart.
hatch.svgPaste once into a page with static bar charts: the patterns #st-hatch-1..8 that .st-chart-bar and .st-swatch-bar fill with. Without it bars fall back to plain colours.
data-st-chart="live" | "failed", st-chart:live / st-chart:failed eventsSet by enhance(); the static plot is hidden on screen only with live.
