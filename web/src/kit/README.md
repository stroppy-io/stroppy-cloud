# Stroppy UI kit

How Stroppy looks, independent of any framework: everything here is read by
the app, and will be by a report page or a site, after the kit moves to
`stroppy-ui`. Adapters to a framework (the Grafana theme, a site's CSS
mapping) live with whoever uses that framework, not here.

| File | What |
|---|---|
| `tokens.json` | The source: palette for dark (graphite) and light, fonts, sizes, radii, spacing, the mark orange. |
| `tokens.ts` | Typed access to the tokens. |
| `tokens.css` | The tokens as `--st-*` variables with the themes (below). Generated by `css.ts`: change `tokens.json`, then `KIT_UPDATE=1 yarn test`. |
| `base.css` | Plain HTML inside `.st-doc`, plus opt-in hooks for meaning (below). |
| `fonts.css`, `fonts/` | Inter and Roboto Mono. |
| `logo.ts`, `logo/mark.svg` | The mark: geometry, and the same as an SVG that takes `--st-mark` (rays, band) and `--st-muted` (cylinder). |
| `chart.ts`, `chart.css` | Charts that look like the app's Grafana panels, drawn by uPlot on the `--st-*` variables; the static-SVG conventions and the progressive contract (below). |
| `hatch.svg` | The bar hatch patterns for static SVG charts, generated from `chart.ts` (`KIT_UPDATE=1 yarn test`). |
| `example.html` | A report page on the bundle: which files to link and how to mount a chart. |

`base.css` hooks, all CSS on the tokens:

| Markup | What it gives |
|---|---|
| `data-tone="success\|warning\|error\|info\|primary\|muted\|mark"` | Meaning: text-level elements and table cells take the colour; the shapes below use it for border, tint, dot. |
| `data-series="1".."8"` | Chart series colour for a legend entry, dot or bar (`--st-series-N`). |
| `.st-tag`, `.st-tags` | A label in a pill; a wrapping row of them. |
| `.st-dot` (`data-pulse`) | A status light; pulsing while something runs. |
| `<aside>` / `.st-callout` | A note; a first `<strong>` is its title. Info unless `data-tone` says otherwise. |
| `.st-stat` in `.st-grid` | A headline number: label, `<strong>` value with `<small>` unit, a note. |
| `.st-panel` with `<header>` | A bordered block with a title row; a table inside goes edge to edge. |
| `.st-grid`, `.st-row` | Equal responsive columns; a wrapping row. |
| `<dl>` | Key–value in two columns. |
| `tr[data-tone]`, `.st-bar` (`--value: 62%`), `table.st-compact` | A tinted row, an inline share bar, denser cells. |
| `<progress>`, `<meter>` | Thin tracks in our colours. |
| `.st-button` (`data-variant="primary\|text"`) | A link or button that is an action. |
| `<nav>` links (`aria-current`), `<details>`, `<mark>`, `<abbr title>` | Pills, a disclosure, a highlight, a dotted hint. |

## Themes

`data-theme` on any element picks the palette, CSS only, nearest one wins:

| Value | Palette |
|---|---|
| `dark`, or no attribute | dark (the default, as in v0.1.0) |
| `light` | light |
| `system` | the reader's `prefers-color-scheme` |

An explicit `dark` or `light` beats the system preference, also inside a
`system` page. Print is light whatever the screen shows. Canvas, panels,
text, controls, borders, tones, focus, chart axes, grid, series and legends
all read the same variables, so every part follows. Charts redraw on a
theme change (the attribute or the system scheme).

## Chart

`mount(target, series, options)` draws series shaped like a run's metrics
(`{ title, unit, points: [[time, value], …] }`, time in seconds or
milliseconds): 1px lines with an 8% fill, the series colours, a quiet grid,
24-hour time labels, a legend under the plot and a tooltip. It follows its
width and theme. In the bundle it is `StroppyChart.mount(...)`.

| Option | |
|---|---|
| `height`, `unit` | plot height (200), axis unit when the series don't say |
| `curve` | `smooth` (default) or `linear` — straight segments, nothing interpolated |
| `time`, `origin` | `clock` (default) or `elapsed` since `origin` (default: first point), labelled `m:ss` |
| `markers` | `[{ at, label, tone? }]` — phases and events, dashed vertical lines |
| `kind`, `categories` | `bars`: grouped bars, one group per category (histogram buckets); points `[index, value]` |
| `label` | accessible name of the drawn chart |

A `null` value is a missing observation: the line breaks and the fill stops
there; a slot that exists only because another series has a point there is
stepped over. Series differ by more than colour: lines by dash
(`--st-dash-N`), bars by hatch (series 1 solid, 2–8 patterned), the same in
static SVG. Nothing is resampled, merged or inferred.

A canvas does not print reliably (a print-time resize clears it before it can
redraw). For charts that must print, use the progressive contract.

## Progressive charts

A page draws its chart without JavaScript — an SVG and a table of the
numbers — and the kit adds the interactive one on top:

```html
<figure class="st-chart-figure">
  <div class="st-chart-static"><svg class="st-chart-svg">…</svg></div>
  <table class="st-chart-data">…</table>          <!-- the page's; never hidden -->
</figure>
<script src="chart.js"></script>
<script>StroppyChart.enhance(figure, series, options)</script>
```

`enhance()` mounts the live chart in a new `.st-chart-live` next to the
static plot; lines default to `curve: 'linear'`, as a static chart joins its
points. Only after the live chart has drawn does the figure get
`data-st-chart="live"` (the static plot is then hidden on screen) and an
`st-chart:live` event fires. Any failure removes the live container, sets
`data-st-chart="failed"`, fires `st-chart:failed` with `detail.error`,
returns `null` and leaves the static chart as it was; with no script at all
nothing changes. It fails on purpose for what it cannot draw faithfully: no
series, an unknown `kind` or `time`, bars without `categories`, a point that
is not `[number, number | null]` — such a chart keeps its static form rather
than an approximation. A second `enhance()` on the same figure replaces the
first cleanly. Print always shows the static plot; a numbers table folded in
`<details>` stays folded on paper, so leave it open (or outside `<details>`)
where the printout needs the numbers. The page owns the
values, units, labels, series order, the SVG and the table; the kit owns the
styles, the live chart and this lifecycle.

Static SVG markup the kit styles (`chart.css`): `.st-chart-svg` root;
`.st-chart-grid`, `.st-axis` groups with lines and `text`; per series a
`g.st-series[data-series="N"]` holding `.st-line` (a gap is a new `M`),
`.st-area`, `.st-point`, `.st-chart-bar` (focusable with a `<title>`);
`g.st-marker[data-tone]` with a line and a label; legend entries with
`svg.st-swatch[data-series]` (a short line in the series' colour and dash) or
`svg.st-swatch-bar[data-series]` (a square in the series' colour and hatch).
Static bars take their hatches from `hatch.svg` — paste it once into the page
(it is a hidden `<svg>` of `<defs>`); without it they fall back to plain
colours. The hatches follow the page's theme (the `<body>`'s), not a nested
`data-theme`.
Text in an SVG scales with its `viewBox`: draw the SVG at the size it is shown
(or close) for axis labels to match the live chart's.

## Bundle

`yarn build:kit` (or `make kit-bundle`) writes `web/dist-kit/stroppy-kit/` and
`stroppy-kit-<version>.tar.gz`: `tokens.json`, `tokens.css`, `fonts.css` with
`fonts/` (and their OFL texts), `base.css`, `logo/`, `chart.js` (uPlot and
`chart.ts` as one script without modules, exposing `window.StroppyChart`),
`chart.css` (uPlot's stylesheet and ours), `hatch.svg`, `example.html`, `VERSION`,
`THIRD_PARTY_NOTICES.md` with `licenses/` (versions and licence texts of what
the kit carries). Everything works offline and from `file:`. A release attaches the
archive; the version is the release's. A single-file report inlines these
files instead of linking them.

Rules: nothing here imports outside the folder except `uplot` (biome enforces
it; tests may use `node:` and `vitest`). A component joins the kit only when two users
need the same non-trivial markup. The showcase is `/kit` in a dev build.
