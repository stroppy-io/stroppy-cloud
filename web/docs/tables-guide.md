# Гайд: информативные таблицы

Правила проектирования таблиц-списков в Stroppy Cloud. Код: `components/DataTable`
(`col.*` фабрики колонок — `columns.tsx`, ячейки — `cells.tsx`, вид таблицы —
`prefs.ts` + `TableSettings.tsx`). Восстановлен по
первоисточникам (NN/g «Data Tables: Four Major User Tasks», Pencil & Paper
«Data Table Design UX Patterns», Carbon / Atlassian / Salesforce / Grafana
table guidelines, Inclusive Components «Data Tables», Smashing «How to
architect a complex web table», uxpatterns.dev) и адаптирован под наш стек
(`@grafana/ui` + `DataTable` на `@tanstack/react-table`). Реализация —
`web/AGENTS.md` §17; здесь — **что** и **почему**, там — **как в коде**.

Документ = текущее состояние, не лог. Правило меняется — правится здесь.

---

## 0. Зачем таблица

Таблица существует ради четырёх задач пользователя (NN/g). Каждая колонка,
контрол и состояние обязаны служить хотя бы одной:

| Задача | Что нужно таблице |
|---|---|
| **Найти** записи по критерию | поиск, фильтры в колонках, сортировка, скан по первой колонке |
| **Сравнить** записи между собой | выравнивание чисел, единицы, sticky-шапка, подсветка строки, sparkline/бары |
| **Посмотреть / изменить** одну запись | клик по строке → деталь; side-panel вместо модалки; никаких аккордеонов |
| **Действовать** над записью/выборкой | 1–2 inline-действия + кебаб; чекбоксы + панель массовых действий |

Перед проектированием ответить: тип данных (числа / текст / смешанное), намерение
(анализ или действия), объём (десятки, сотни, тысячи), нужна ли правка на месте.
Если ответы «мало свойств, читать как список» — это не таблица, а список карточек.

## 1. Информационная архитектура колонок

1. **Первая колонка — человекочитаемый идентификатор** (имя + подзаголовок), не
   UUID и не статус. По ней пользователь сканирует список сверху вниз.
2. **Порядок колонок = порядок важности** для задачи «найти/сравнить», связанные
   поля рядом (база + топология, tps + p99, старт + длительность).
3. **5–7 колонок видны по умолчанию**; свыше 10 — обязателен переключатель
   видимости колонок и сброс к умолчанию. Предпочтения хранятся (localStorage,
   ключ `stroppy.table.<id>`).
4. **Не дублировать**: то, что есть в заголовке, не повторять в ячейке
   («postgres 17», не «kind: postgres, version: 17»); единицы измерения — в
   заголовке («p99, ms»), не в каждой ячейке, если единица одна на колонку.
5. **Технические имена полей — не заголовки**. Заголовок 1–3 слова, на языке
   пользователя, с единицей.
6. **Вторичная информация — подстрокой** под основным значением (серым,
   `bodySmall`), не отдельной колонкой: описание под именем, «1 запуск · вчера»
   под последним запуском.
7. **Составные значения — одна ячейка, один смысл**: «база» = kind + version +
   badge топологии; «нагрузка» = скрипт + «+N сегментов». Не размазывать сущность
   по трём колонкам, если сравнивать будут её целиком.
8. **Сводка над таблицей** (счётчики по статусам, итоги) — когда пользователю
   важно понять «сколько всего/сколько с проблемой» до чтения строк.

## 2. Типы ячеек

Ячейка — самая маленькая единица; выбирается по типу данных, а не по вкусу.

| Тип | Как | Когда |
|---|---|---|
| **Идентификатор** | жирное имя + серая подстрока, ellipsis + tooltip полного | первая колонка |
| **Текст** | слева, ellipsis, `title` при усечении | описание, автор, метка |
| **Число** | справа, моноширинный, одинаковая точность в колонке, единица в заголовке | tps, p99, длительность, размер |
| **Число + смысл** | число + инлайн-бар (gauge) или sparkline | когда важно сравнить по колонке, не прочитать |
| **Статус** | иконка + цвет + текст (цвет никогда один) | статус запуска/теста/валидации |
| **Перечисление** | `Badge`/`Tag` нейтрального цвета; цвет — только для сигналов | kind, protocol, scope |
| **Теги** | до 3 pill + «+N» | tags |
| **Дата/время** | относительное («21 час назад») + абсолютное в `title`; колонка справа | created/started/updated |
| **Ссылка на сущность** | имя как ссылка, иконка типа, hover | тест ← запуск, база ← тест |
| **Булево** | `Switch` только если правится на месте; иначе иконка check/— | enabled |
| **Прогресс** | тонкая полоска под текстом статуса; у запуска — сегментная по этапам (`runStageProgress`): пройденные залиты, текущий — на % этапа, число в подписи = % этапа | running |
| **Тренд** | sparkline последних N значений + стрелка | тесты (последние запуски), рейтинг |
| **Действия** | кебаб (`ellipsis-v`) + до 2 inline-иконок | последняя колонка, sticky right |

Правила:
- «—» (тире) для отсутствующего значения; никогда пусто, `null`, `0` вместо
  «нет данных».
- Цвет — сигнал (ошибка/успех/внимание), не декорация. В строке не больше одного
  цветного акцента помимо статуса.
- Иконка без текста допустима только в узких колонках (статус, триггер) — тогда
  обязателен tooltip и заголовок колонки с подписью-иконкой + `aria-label`.

## 3. Выравнивание, типографика, плотность

- Текст — слева, числа — справа, заголовок — как содержимое колонки. Центр —
  только для иконок в узких колонках. Центрирование текста ломает скан.
- Числа — моноширинным (`fontFamilyMonospace`), одинаковое число знаков после
  запятой в колонке, тысячи с разделителем.
- Вертикальное выравнивание — по центру для 1–3 строк; сверху для длинного
  многострочного контента.
- Плотность: три ступени по вертикальному отступу ячейки — «Плотно» (4px,
  подстрока имени скрыта, строка ≈32px), «Обычно» (8px, строка ≈40px, с
  подстрокой ≈52px), «Свободно» (12px). По умолчанию «Обычно»; переключатель —
  в меню «Вид таблицы», хранится per-viewer.
- Разделители: горизонтальная линия `border.weak` 1px; вертикальных — нет.
  Зебра — только если в строках нет hover/selection состояний (у нас есть → нет
  зебры).
- Hover-подсветка строки обязательна; selected — `action.selected` +
  left-accent.
- Усечение — ellipsis по умолчанию; wrap — только по явному переключателю
  («Перенос»), как в логах.
- Минимальная ширина текстовой колонки 120px, числовой 80px, иконочной 40–56px.
  Свободное место распределяется в идентификатор и текстовые колонки.

## 4. Шапка: сортировка и фильтры

Заголовок колонки — три слота `[⇅ сорт] Метка [⛃ фильтр]` (эталон main-v0):
- Сорт — тристабильный: нейтрально → по возрастанию → по убыванию → нейтрально.
  Индикатор всегда виден (нейтральная иконка приглушённая), активный — primary.
  Сортировка одной колонкой; «умолчание» = серверный default (обычно новые
  сверху). Сортировать можно **каждую** колонку, где это имеет смысл; сервер
  обязан поддерживать ключ, клиентская сортировка страницы запрещена (врёт при
  пагинации). Исключение — ограниченные списки без пагинации (рейтинг).
- Фильтр колонки — поповер по её типу: чек-лист со счётчиками (facets) для
  перечислений, текст для строк, диапазон для дат и чисел. Активный фильтр —
  залитая иконка primary. Поповер не закрывается от refetch; авто-обновление
  ставится на паузу, пока он открыт.
- Заголовок фиксируется (sticky top) при вертикальном скролле.
- Ширина слотов резервируется всегда, чтобы метки колонок стояли на одной линии.

## 5. Тулбар над таблицей

Слева направо: **поиск** (по имени/описанию, debounce 300 мс, применяется на
Enter/паузе) → **быстрые переключатели** (`Checkbox`: «Только избранные»,
«Живые стенды», «Показать удалённые») → **чипсы активных фильтров** с крестиком
и «Сбросить фильтры» → справа: **счётчик** «Показано N из M» → **размер
страницы** → **авто-обновление** (Off/5s/15s/30s/1m + «Обновить сейчас»).

- Быстрые пресеты («Все / Выполняются / Мои») — как чипы фильтра, не как вторая
  система навигации: они лишь ставят фильтры колонок.
- Все контролы одной высоты (32px, `size="md"`), в одну строку, перенос на
  узком экране.
- Панель **массовых действий** появляется вместо тулбара при выборе ≥1 строки:
  «Выбрано N · [Сравнить] [Экспорт] [Удалить]» + «Снять выбор». Есть «выбрать
  все на странице».

## 6. Действия

- Клик по строке (по всей, `<a>` для cmd-click) — открыть деталь. Ссылки внутри
  ячеек (автор, база) ведут в свои сущности, не в строку.
- Inline-действия — максимум два самых частых (избранное, запустить); остальное —
  в кебабе. Кебаб рендерит **все** действия сущности; недоступные — `disabled` с
  причиной в описании (не скрываются). Деструктивные — в конце, отделены,
  `destructive`, с подтверждением; после удаления — undo/тост.
- Действия строки не всплывают в навигацию строки.
- Кебаб и избранное — **sticky right**, всегда видны при горизонтальном скролле.
- Действие с побочным эффектом (запустить, удалить, отозвать) — подтверждение
  или явная кнопка; редактирование на месте — только для одного поля (переключить
  enabled, переименовать).

## 7. Состояния

| Состояние | Как показывать |
|---|---|
| Загрузка первая | скелет строк по высоте таблицы (не спиннер по центру) |
| Обновление | старые данные остаются (`keepPreviousData`), иконка sync крутится |
| Пусто (нет данных) | иллюстрация-иконка + текст + primary-действие («Создать тест») |
| Пусто (фильтр) | «Ничего не найдено по фильтрам» + «Сбросить фильтры» |
| Ошибка | `ErrorState` с retry внутри области таблицы, шапка остаётся |
| Частичные данные | «—» в ячейках, никаких прочерков-заглушек в стиле «n/a» |
| Догрузка (infinite) | строка-сентинел с «Показать ещё» + авто при скролле |
| Отфильтровано | чипсы фильтров + залитые иконки в шапке |
| Выбрано | панель массовых действий + подсветка строк |

## 8. Навигация по данным

- Курсорная пагинация сервера; на клиенте — «Показать ещё» + infinite scroll;
  размер страницы выбирается (25/50/100).
- Виртуализация с ≥100 строк.
- Сохраняется в **URL**: поиск, фильтры, сортировка, размер страницы. Back
  возвращает к тому же виду; ссылка на вид разделяема.
- Сохраняется в **localStorage**: видимость/порядок колонок, плотность, интервал
  авто-обновления.
- Не сохраняется: выбор строк, открытые поповеры.

---

## 9. Sticky и ширина

- Шапка sticky top; идентификатор — sticky left, если колонок > 8; действия и
  избранное — sticky right всегда.
- Таблица шире контейнера — горизонтальный скролл **внутри** таблицы, никогда
  страницы. По вертикали — то же: таблица-список заполняет остаток экрана и
  прокручивает строки внутри себя под закреплённой шапкой; страница не
  скроллится (один скролл на экран, `web/AGENTS.md` §18). Ключевые данные (идентификатор, статус, действия) не должны требовать
  горизонтального скролла.
- Ширины: фиксированные для иконочных/числовых/дат, гибкие для текста;
  `table-layout: fixed`, `minWidth` суммируется, чтобы гибкие не схлопывались.

---

## 10. Доступность и клавиатура

- Семантика `<table>/<thead>/<th scope="col">`, `aria-label` таблицы,
  `aria-sort` на сортируемых, `role="button"` на кнопках сортировки с подписью
  «Сортировать по X по возрастанию».
- Tab по интерактивным элементам; Enter открывает строку; Space — чекбокс;
  Escape закрывает поповер/меню; фокус после действия остаётся на ближайшем
  элементе (после удаления — следующая строка).
- Контраст 3:1 у индикаторов, цвет не единственный носитель смысла.

---

## 11. Мобильный / узкий экран

Не приоритет продукта, но: до 720px таблица показывает только идентификатор,
статус и действия; остальное — раскрытие строки. Никакой отдельной «карточной»
вёрстки сейчас не делаем.

---

## 12. Чек-лист приёмки таблицы

- [ ] первая колонка — имя + подстрока, кликабельна, ellipsis+tooltip
- [ ] колонки в порядке важности, ≤ 7 видимых по умолчанию, остальное — в
      переключателе видимости
- [ ] у каждой колонки правильный тип ячейки (§2), числа справа и моно, единица
      в заголовке
- [ ] каждая колонка сортируется на сервере или явно `sortKey: undefined` с
      причиной
- [ ] у каждой перечислимой/датовой/числовой колонки — фильтр нужного типа
- [ ] тулбар по §5, все контролы 32px в одну линию
- [ ] кебаб со всеми действиями, disabled с причиной, sticky right
- [ ] состояния §7 реализованы (скелет, пусто×2, ошибка, догрузка)
- [ ] URL/localStorage состояние по §8
- [ ] нет горизонтального скролла страницы; ключевые данные видны без скролла
- [ ] строки ru/en в локалях, заголовки на языке пользователя
- [ ] проверено на реальном сервере, тёмная и светлая темы

## 13. Профили таблиц (выведены из эталона §14)

Правила эталона, общие для всех: статус — иконкой в первой колонке; идентификатор —
имя-ссылка + ☆-индикатор избранного + бейджи (keep, теги) и вторая строка (описание
/ цель / причина); составные сущности — одна колонка в две строки (`col.stack`);
несколько чисел — одна колонка с меню сортировки (`sortOptions`); время — одна
колонка (когда + вторичное время/длительность); автор и «изменён» скрыты по
умолчанию; **никаких кнопок в строке** — избранное и всё прочее в кебабе;
список — `Page fill` + `DataTable fill`; видимых по умолчанию ≤ 7.

**Тесты.** Статус (готов/черновик/невалиден) · Тест (имя, ☆, теги / описание) ·
База (движок+версия / топология · N узлов; сорт.-меню: движок, база) · Нагрузка
(скрипт +N / протокол · stroppy · N сегм. · VU) · Последний запуск (иконка статуса +
когда / тренд QPS + «N запусков»; сорт. last_run_at) · Провайдер (профиль / размеры;
скрыта) · Изменён (скрыта) · Автор (скрыта) · кебаб: открыть, запустить, изменить,
дублировать, валидировать, запуски теста, ☆, копировать ссылку/ID, удалить.

**Базы данных.** Базa (имя, ☆, теги / описание) · Движок (kind+version / образ) ·
Топология (метка · N узлов / требования ролей) · Использование («в N тестах»,
сорт. нет) · Изменён (когда / автор) · кебаб: открыть, изменить, дублировать,
новый тест из базы, ☆, копировать ID, удалить (недоступно, пока используется).

**Нагрузки.** Нагрузка (имя, ☆, теги / описание) · Протокол (протокол / stroppy X;
сорт.-меню: протокол, версия) · Сегменты (скрипты +N / N сегм. · VU · длительность) ·
Раннер (cpu/mem; скрыта) · Использование · Изменён · кебаб как у баз.

**Сьюты.** Сьют (имя, ☆, теги / описание) · Состав (N тестов / N ячеек · оси) ·
Последний прогон (иконка статуса + когда / прошло·упало ячеек) · Расписания (ближайший
запуск / N расписаний) · Изменён (скрыта) · кебаб: открыть, запустить, расписание,
изменить, дублировать, ☆, копировать ID, удалить.

**Расписания.** Статус (активно / пауза / ошибка последнего запуска) · Расписание
(имя / цель-ссылка) · Когда (cron по-человечески / TZ, raw cron в тултипе) · Следующий
(когда / «через N») · Последний (иконка статуса + когда) · Автор (скрыта) · кебаб:
открыть, запустить сейчас, включить/приостановить, изменить, копировать ID, удалить.

**Публикации.** Состояние (активна / отозвана / истекла) · Публикация (заголовок /
цель-ссылка) · Доступ (scope) · Просмотры (число) · Срок (истекает / создана) · кебаб:
открыть публичную ссылку, копировать ссылку, изменить, отозвать, удалить.

**Рейтинг.** Место · Запуск (имя-ссылка / тенант · автор) · База (stack) ·
Нагрузка (stack) · Значение (число + полоска) · Провайдер (профиль / лига) · Дата ·
клиентская сортировка, без кебаба (переход по строке).

**Вторичные таблицы** (внутри страниц/вкладок, админка, настройки): те же фабрики и
ячейки, кебаб вместо кнопок, пустые состояния через `empty`. Таблица, которая —
основной контент страницы (админ: запуски/тенанты/пользователи; аудит; участники,
токены, вебхуки), — `Page fill` + `DataTable fill`; таблица внутри вкладки растёт
естественно, скроллится тело вкладки (§18 AGENTS).

**Данные не влезают — баг.** Каждая текстовая ячейка обрезается многоточием и несёт
полный текст в тултипе (`title`); ширина колонки ≥ ширины заголовка + 48px (слоты
сортировки/фильтра); длинные пары — в две строки, а не в одну.
